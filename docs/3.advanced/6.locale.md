# Dashboard language

The dashboard interface ships in English. `eponyme.locale` replaces it with another language:
buttons, labels, state messages, validation errors and the strings the API returns.

It never touches your content, your schema labels, or your site's own `@nuxtjs/i18n` setup. Those
are different problems, and this one deliberately stays small.

## Use a language

Catalogues live in a separate package, so a translation can be corrected without waiting for a
version of Eponyme:

```bash
npm i -D @eponyme/locale
```

```ts [nuxt.config.ts]
import { fr } from '@eponyme/locale/fr'

export default defineNuxtConfig({
  eponyme: {
    locale: fr(),
  },
})
```

Without the option, the dashboard is in English and there is nothing to install.

Each language is its own import. An index would load every catalogue the moment `nuxt.config` is
evaluated, for the one language you end up using.

::note
`locale: fr` passes the function instead of its result, and Eponyme refuses it at setup with a
message naming the fix. Without that check the failure surfaces much later in the build, in a form
that points nowhere.
::

## Change a few words

The argument overrides individual messages, without forking the catalogue:

```ts
locale: fr({
  'array.add': 'Ajouter un bloc',
  'collection.create': '+ Nouvel article',
}),
```

For the wording of one collection's create button, prefer `addLabel` on the collection itself —
it is more specific and does not travel across your whole dashboard.

## One language per build

The catalogue is resolved during the module's setup, merged over English, and inlined into a
virtual module. There is no loading at runtime, no reactive state, and no way to switch language
from the interface.

This is a deliberate limit rather than a missing feature. An administration is used by a known
team, and a runtime switch would buy a rare convenience in exchange for lazy loading, an extra
reactive dependency in every component, and hydration mismatches.

Because it is resolved at build time, the same catalogue serves the browser and the server: a
validation message reads the same whether it comes from the editor as you type or from the API
after a rejected save.

## Dates and numbers

`code` is a BCP 47 tag, handed to `Intl` wherever the dashboard formats a date, a number or a
list. A French interface shows `7 août 2026, 15:28`, and a list of accepted protocols reads
`mailto: ou tel:`.

With no locale configured, the code is `en-GB` — day-first and 24-hour.

## A partial catalogue

English is merged underneath every catalogue, so a key the translation does not carry reads in
English instead of showing its own name to an editor. The build lists what is missing:

```
[eponyme] WARN  The fr-FR catalogue is missing 2 keys, which fall back to English:
  - select.empty
  - field.color
```

That is the cost of keeping translations on their own release cycle, and the warning is what keeps
it from being silent.

## Add a language

The reference catalogue is shipped with Eponyme and is the source of truth for the keys:

```ts
import reference from '@karibsen/eponyme/locales/en.json'
```

A catalogue is a flat object of `<area>.<action>` keys, and a factory that merges overrides:

```ts [my-locale.ts]
import type { EponymeLocaleDefinition } from '@karibsen/eponyme'
import messages from './my-locale.json'

export function myLocale(overrides: Record<string, string> = {}): EponymeLocaleDefinition {
  return {
    code: 'pt-PT',
    messages: { ...messages, ...overrides },
  }
}
```

Nothing requires the catalogue to live in a package — the option takes any object of this shape,
so a single application can keep one in its own repository.

### Placeholders and plurals

`{name}` is replaced from the values Eponyme passes. A message with plural forms separates them
with `|`, in this order: none, one, many.

```json
{
  "array.counterMax": "{count} / {max} éléments | {count} / {max} élément | {count} / {max} éléments"
}
```

`plural` maps a count to one of those indices. The default is
`count => count === 0 ? 0 : count === 1 ? 1 : 2`, which suits English, French and Spanish; what
differs between them is the wording of each form, not which one is picked. A language that groups
counts differently declares its own rule.

::warning
`plural` is serialised into the generated catalogue with `Function.prototype.toString()`, so it has
to stand alone. A closure over an import or an outer variable does not survive.
::

Contributions go to [`@eponyme/locale`](https://github.com/eponymejs/locale), where a CI check
fails when a catalogue has drifted from the reference.
