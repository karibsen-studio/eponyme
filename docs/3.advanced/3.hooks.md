# Server hooks

Eponyme emits Nitro hooks around every content write and every form submission. Listen from a server
plugin.

```ts [server/plugins/eponyme.ts]
export default defineNitroPlugin((nitroApp) => {
  nitroApp.hooks.hook('eponyme:entry:published', async ({ name, collection }) => {
    await purgeCdnCache(collection ? `/${collection.name}/${collection.slug}` : `/${name}`)
  })
})
```

| Hook | When | Blocking |
|---|---|---|
| `eponyme:entry:beforeSave` | Before any editorial write | **yes** |
| `eponyme:entry:saved` | After a draft save | no |
| `eponyme:entry:published` | After a publication | no |
| `eponyme:entry:unpublished` | After content leaves the public site | no |
| `eponyme:entry:scheduled` | After publication dates are scheduled | no |
| `eponyme:entry:unscheduled` | After publication dates are cleared | no |
| `eponyme:entry:restored` | After a history version was restored as the draft | no |
| `eponyme:entry:trashed` | After an entry was moved to the trash | no |
| `eponyme:entry:untrashed` | After an entry left the trash | no |
| `eponyme:entry:purged` | After an entry and its history were deleted for good | no |
| `eponyme:form:beforeSubmit` | Before a managed submission is stored | **yes** |
| `eponyme:form:submitted` | After a managed submission was stored | no |
| `eponyme:cache:failed` | After the shared cache tier could not be reached | no |

## Blocking hooks

Throwing inside a `before` hook refuses the operation with a `422` carrying your message, which lets
you enforce a rule the schema cannot express. Mutating `data` amends the payload before it is
validated and written.

```ts
nitroApp.hooks.hook('eponyme:entry:beforeSave', ({ name, data }) => {
  if (name === 'homepage' && String(data.title).includes('TODO'))
    throw new Error('Remove the TODO from the title before saving.')

  data.updatedBy = 'automation'
})
```

## Notification hooks

A notification hook runs after the operation has landed. Throwing there does **not** fail the write:
the error is logged, recorded in the audit log as `hook.failed`, and the operation still reports
success. A publication that reached the database must not be reported as a failure the editor cannot
act on.

The call is not retried: one call reaches every listener of that name, so trying again would re-run
the ones that already succeeded - a second webhook, a second email. An effect that must not be lost
- a CDN purge, an external index - needs its own queue on your side; the audit entry tells you when
one was missed.

```ts
nitroApp.hooks.hook('eponyme:form:submitted', async ({ form, id, data }) => {
  await sendSlackMessage(`New ${form} submission ${id} from ${data.email}`)
})
```

## Reporting a cache failure

`eponyme:cache:failed` fires when the shared cache tier could not be read, written or invalidated.
Nothing failed for the visitor, reads fall back to PostgreSQL, but an invalidation that did not
land means other instances keep serving the previous content until their window expires, which is
worth knowing about:

```ts
nitroApp.hooks.hook('eponyme:cache:failed', ({ operation, key, error }) => {
  if (operation === 'invalidate') reportToSentry(error, { key })
})
```

Eponyme logs the first failure of each kind and stays quiet for a minute after it, but the hook
fires every time, so a listener that reports somewhere should throttle on its own.

## Context

An entry hook receives the entry name, its data, and `collection` when the entry belongs to one:

```ts
{
  name: 'articles/my-article',
  data: { /* the entry content */ },
  collection: { name: 'articles', slug: 'my-article' },
  action: 'schedule',
  status: 'published',
  publishedAt: '2026-08-08T10:00:00.000Z',
  scheduledPublishAt: '2026-08-09T08:00:00.000Z',
  scheduledUnpublishAt: null,
}
```

A form hook receives the form name, the validated data, and the submission id once it exists.

Hook names and their contexts are typed as soon as the module is installed, so a plugin gets
completion and checking without importing anything. The context types are exported as
`EponymeEntryContext`, `EponymeEntryBeforeSaveContext`, `EponymeEntryTrashContext`,
`EponymeFormSubmissionContext` and `EponymeCacheFailureContext` when you need to annotate a handler
shared by several hooks.
