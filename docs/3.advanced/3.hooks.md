# Server hooks

Eponyme emits Nitro hooks around every content write and every form submission. Listen from a server
plugin.

```ts [server/plugins/eponyme.ts]
export default defineNitroPlugin((nitroApp) => {
  nitroApp.hooks.hook('eponyme:entry:published', async ({ name, collection }) => {
    await purgeCdnCache(collection ? `/${collection.name}/${collection.slug}` : `/${name}`)
  })
})
```

| Hook | When | Blocking |
|---|---|---|
| `eponyme:entry:beforeSave` | Before a draft save or a publication | **yes** |
| `eponyme:entry:saved` | After a draft save | no |
| `eponyme:entry:published` | After a publication | no |
| `eponyme:entry:restored` | After a history version was restored as the draft | no |
| `eponyme:entry:trashed` | After an entry was moved to the trash | no |
| `eponyme:entry:untrashed` | After an entry left the trash | no |
| `eponyme:entry:purged` | After an entry and its history were deleted for good | no |
| `eponyme:form:beforeSubmit` | Before a managed submission is stored | **yes** |
| `eponyme:form:submitted` | After a managed submission was stored | no |

## Blocking hooks

Throwing inside a `before` hook refuses the operation with a `422` carrying your message, which lets
you enforce a rule the schema cannot express. Mutating `data` amends the payload before it is
validated and written.

```ts
nitroApp.hooks.hook('eponyme:entry:beforeSave', ({ name, data }) => {
  if (name === 'homepage' && String(data.title).includes('TODO'))
    throw new Error('Remove the TODO from the title before saving.')

  data.updatedBy = 'automation'
})
```

## Notification hooks

A notification hook runs after the operation has landed. Throwing there does **not** fail the write:
the error is logged and the operation still reports success. A publication that reached the database
must not be reported as a failure the editor cannot act on.

```ts
nitroApp.hooks.hook('eponyme:form:submitted', async ({ name, id, data }) => {
  await sendSlackMessage(`New ${name} submission ${id} from ${data.email}`)
})
```

## Context

An entry hook receives the entry name, its data, and `collection` when the entry belongs to one:

```ts
{
  name: 'articles/my-article',
  data: { /* the entry content */ },
  collection: { name: 'articles', slug: 'my-article' },
}
```

A form hook receives the form name, the validated data, and the submission id once it exists.
