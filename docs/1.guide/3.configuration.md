# Configuration

Everything lives under the `eponyme` key of `nuxt.config`.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@karibsen/eponyme'],
  eponyme: {
    prismaClient: '~~/server/utils/prisma',
    dashboardPath: '/__eponyme',
    previewPaths: {
      homepage: '/',
      articles: '/articles/:slug',
    },
    colorPresets: [
      { label: 'Ink', value: '#171714' },
      '#ffffff',
    ],
    auth: {
      sessionDurationDays: 7,
    },
    cacheSeconds: 5,
    browserCacheSeconds: 30,
    cdnCacheSeconds: 300,
  },
})
```

## Options

| Option | Default | What it does |
|---|---|---|
| `prismaClient` | *required* | Module specifier of a server file whose default export is an initialised `PrismaClient`. The build fails without it |
| `dashboardPath` | `/__eponyme` | Route the dashboard is served on. Surrounding slashes are normalised, so `__eponyme` and `/__eponyme/` are equivalent |
| `previewPaths` | `{}` | Public route rendering each entry. A collection value must contain `:slug` |
| `colorPresets` | `[]` | Palette offered by every color field, unless the field sets its own `presets` |
| `auth.sessionDurationDays` | `7` | Session lifetime in days, counted from sign-in and never extended by activity |
| `cacheSeconds` | `5` | How long a server instance may reuse content it has already read. `0` disables it |
| `browserCacheSeconds` | `30` | How long a browser may reuse published content. `0` disables it |
| `cdnCacheSeconds` | `300` | How long a CDN may reuse published content. `0` disables it |

## previewPaths

This map is read three times over: to build preview URLs for the dashboard, to list the sitemap,
and to attach cache tags to those routes so a publication can purge them.

```ts
previewPaths: {
  // a singleton, by its exact name
  'homepage': '/',
  'pages/legal': '/legal',
  // a collection, by its name, with `:slug` replaced per entry
  'articles': '/articles/:slug',
}
```

An entry left out of the map is still editable: it simply has no public URL Eponyme can name, so
it gets no preview, no sitemap entry and no cache tag.

## The three cache windows

They are deliberately different, because they cannot be invalidated in the same way.

| Window | Sent as | Can it be purged? |
|---|---|---|
| `cacheSeconds` | nothing, it is in-memory per server instance | a save clears it on the instance that served it |
| `browserCacheSeconds` | `max-age` | **no**, never, so keep it short |
| `cdnCacheSeconds` | `s-maxage`, plus `stale-while-revalidate` twelve times longer | yes, by tag |

## Roles

Roles are intentionally small:

- `owner` manages content and users.
- `editor` manages content.
- `viewer` has read-only dashboard access.

Permissions are enforced on the server, never in the interface alone. Purging an entry for good is
the only irreversible operation, so it is reserved to `owner`.
