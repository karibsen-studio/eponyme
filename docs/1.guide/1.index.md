# Getting Started

Eponyme turns a TypeScript file into a content manager for a Nuxt application. You declare the
shape of your content, and the module gives you defaults, validation, PostgreSQL persistence, a
server API, typed composables, and a generated dashboard your client can use.

There is no separate CMS to host, no second deployment and no content API to keep in sync. Your
application keeps its own Prisma client, its own database and its own migrations.

## Install

1. Add the package:

   :pm-install{name="@karibsen/eponyme"}

2. Register the module and point it at your Prisma client:

   ```ts [nuxt.config.ts]
   export default defineNuxtConfig({
     modules: ['@karibsen/eponyme'],
     eponyme: {
       prismaClient: '~~/server/utils/prisma',
     },
   })
   ```

3. Declare your content in `eponyme.config.ts`, at the root of the application:

   ```ts [eponyme.config.ts]
   export default defineEponymeConfig({
     homepage: {
       title: field.string({ label: 'Title', required: true, defaultValue: 'Welcome' }),
       introduction: field.textarea({ label: 'Introduction', maxLength: 160 }),
     },
   })
   ```

4. Add the required models to your Prisma schema, then migrate.

   :read-more{to="/guide/installation"}

5. Start the server:

   :pm-run{script="dev"}

The dashboard is at `/__eponyme`. On the first start, Eponyme creates an `EponymeOwner` account
and prints a temporary password once in the server console.

## Read your content

```vue [app/pages/index.vue]
<script setup lang="ts">
const { data } = useEponyme('homepage')
</script>

<template>
  <h1>{{ data?.title }}</h1>
  <p>{{ data?.introduction }}</p>
</template>
```

`data` is typed from your config: `data.title` is a `string`, and a field you never declared is a
compile error rather than a runtime surprise.

::note
Only published content reaches the public. A draft stays invisible until someone publishes it, and
unreachable to anyone without an authenticated session.
::
