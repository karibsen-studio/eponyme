# Collections

A singleton is one entry: a homepage, a settings page. A collection is repeatable content:
articles, projects, team members.

```ts [eponyme.config.ts]
export default defineEponymeConfig({
  articles: collection({
    label: 'Articles',
    description: 'Stories published on the site.',
    titleField: 'title',
    slugField: 'slug',
    fields: {
      title: field.string({ label: 'Title', required: true }),
      slug: field.slug({ label: 'Slug', required: true }),
      excerpt: field.textarea({ label: 'Excerpt', maxLength: 200 }),
      body: field.richText({ label: 'Body' }),
    },
  }),
})
```

`titleField` is what the dashboard lists entries by. `slugField` builds the entry name:
an entry of `articles` with slug `my-article` is stored as `articles/my-article`.

The create button reads `+ New Article`, singularised from the collection name. `addLabel` replaces
that text outright, including the `+`:

```ts
addLabel: 'Écrire un article',
```

::note
A slug is immutable once the entry exists. Renaming it would change a public URL that visitors and
search engines already hold, so Eponyme refuses the change rather than breaking the link.
::

## Reading a collection

```vue
<script setup lang="ts">
const { entries, total, pending, error, refresh } = useEponymeCollection('articles', {
  orderBy: 'publishedAt',
  order: 'desc',
  take: 10,
  skip: 0,
})
</script>
```

`entries` carries only published entries. Each one exposes `slug`, `title`, `data`, `status`,
`publishedAt` and `updatedAt`. `total` counts the matches before `take` and `skip`, so it can drive
a pager directly.

Sorting accepts the entry metadata (`updatedAt`, `publishedAt`, `title`, `slug`) and any field of
the collection. A key that does not exist is reported as a `400` rather than silently ignored.

## Reading one entry

```vue
<script setup lang="ts">
const route = useRoute()
const { data, status, publishedAt, pending, error } = useEponymeCollectionEntry(
  'articles',
  String(route.params.slug),
)
</script>
```

## The trash

Deleting an entry moves it to the trash. It keeps its row, its slug and its whole history, and
reads as missing everywhere else: not in a listing, not in the sitemap, not through the API.

```ts
// server side
const service = useEponymeService()
await service.listCollectionTrash('articles')
await service.restoreCollectionEntry('articles', 'my-article')
await service.purgeCollectionEntry('articles', 'my-article')
```

A trashed entry still owns its slug, so creating a new entry with that slug is refused with a
message naming the trash, rather than overwriting what is waiting there.

::warning
Purging is the only irreversible operation: it deletes the entry and its entire history. It is
reserved to the `owner` role.
::
