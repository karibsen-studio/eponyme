# Composables

Every composable is auto-imported and typed from your `eponyme.config.ts`. A name that does not
exist in the config is a compile error, not a runtime `undefined`.

## useEponyme

Reads and saves one singleton, or one collection entry by its full name.

```ts
const { data, status, publishedAt, pending, error, errors, refresh, save } = useEponyme('homepage')
```

| Returned | What it is |
|---|---|
| `data` | The content, typed from the config |
| `status` | `'draft'` or `'published'` |
| `publishedAt` | ISO date of the last publication, or `null` |
| `pending` | True while loading **or** saving |
| `error` | Transport error |
| `errors` | Validation errors from the last save, keyed by field path |
| `refresh` | Re-reads, bypassing every cache |
| `save` | `save()` publishes what is held; `save(patch, 'draft')` saves a draft |

```ts
const editor = useEponyme('homepage', { version: 'draft' })
await editor.save({ title: 'New title' }, 'draft')
await editor.save(editor.data.value, 'publish')
```

The `raw` option keeps `{{ variables }}` unresolved, which is what the dashboard editor needs to
show the source text.

## useEponymeCollection

```ts
const { entries, total, pending, error, refresh } = useEponymeCollection('articles', {
  orderBy: 'publishedAt',
  order: 'desc',
  take: 10,
  skip: 0,
})
```

Published entries only. `total` ignores `take`, so it can drive a pager.

## useEponymeCollectionEntry

```ts
const { data, status, publishedAt, pending, error, refresh } = useEponymeCollectionEntry('articles', slug)
```

## useEponymeForm

```ts
const { fields, values, errors, pending, submitted, honeypot, submit, reset } = useEponymeForm('contact', {
  async onSubmit(data) { /* custom mode */ },
})
```

## useEponymeAuth

```ts
const { user, role, permissions, can, login, logout, refresh } = useEponymeAuth()

const canPublishArticles = can('content.publish', {
  kind: 'collection',
  name: 'articles',
})
```

Useful for hiding an affordance on your own pages. It is never the protection itself: the same
permission is enforced on the server.

## useEponymeConfig

Returns the module's public configuration: `previewPaths`, `dashboardPath` and `colorPresets`.

## Server utilities

Auto-imported in your server code, so a Nuxt sitemap integration or your own route never has to make
an internal HTTP request:

```ts
// Every public URL Eponyme knows about
const entries = await getEponymeSitemapEntries()

// Validate a submission in your own handler
const result = validateEponymeForm('contact', body)

// The tags a CDN purge has to invalidate
const tags = getEponymeCacheTags(name, collection)
```

::note
These composables use `useRequestFetch()` internally so cookies and headers travel during SSR. Do
not replace it with a global `$fetch` in your own wrappers, or a draft preview stops authenticating.
::
