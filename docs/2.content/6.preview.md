# Previews

Declare where an entry is rendered and Eponyme can do three things with it: preview a draft on the
real page, list the URL in a sitemap, and tag the route so a publication can purge it. All three
come from one map.

```ts [nuxt.config.ts]
eponyme: {
  previewPaths: {
    'homepage': '/',
    'pages/legal': '/legal',
    'articles': '/articles/:slug',
  },
}
```

## How a preview works

The dashboard opens your public route in a frame with three query parameters:

| Parameter | Value |
|---|---|
| `__eponyme_preview` | The full entry name, `articles/my-article` |
| `__eponyme_preview_version` | `draft`, `published`, or a numeric history id |
| `__eponyme_preview_token` | A fresh token per load, so nothing is served from the frame's history |

`useEponyme()` and `useEponymeCollectionEntry()` read those parameters on their own, so a page needs
no preview-specific code. The server requires at least a `viewer` session for anything unpublished,
and an anonymous visitor who guesses a preview URL sees only published content.

::important
An unpublished version is fetched **from the browser only**, never rendered on the server. A public
route belongs to your application, which may cache it: nitro stores the rendered response and
overwrites the `Cache-Control` Eponyme sets, so a server-rendered draft would be replayed to
anonymous visitors from that cache, without the session being re-checked.

The visible consequence: the preview panel shows its loading state briefly instead of arriving
already rendered, and `useSeoMeta` does not see draft values in a preview.
::

An explicit `version` option is not a preview: that is the dashboard reading its own entry on its
own authenticated routes, and it stays server-rendered.
