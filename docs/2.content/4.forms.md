# Public forms

`form()` is a top-level primitive, beside `collection()`. A form owns a schema, its submissions, its
permissions and its API route, so it is not stored as an ordinary field value.

```ts [eponyme.config.ts]
import { defineEponymeConfig, field, form } from '@karibsen/eponyme/config'

export default defineEponymeConfig({
  contact: form({
    label: 'Contact',
    fields: {
      name: field.string({ label: 'Name', required: true, minLength: 2 }),
      email: field.email({ label: 'Email', required: true }),
      phone: field.phone({ label: 'Phone', defaultCountry: 'FR' }),
      message: field.textarea({ label: 'Message', required: true, minLength: 10 }),
    },
    submission: { mode: 'managed' },
  }),
})
```

Only field types a visitor can meaningfully fill in are accepted: `string`, `textarea`, `email`,
`phone`, `url`, `number`, `boolean`, `select`, `radio` and `checkboxGroup`. Anything else is an
authoring concern and `form()` throws at build time rather than rendering something nobody can use.

## Two submission modes

::tabs
```ts [custom (default)]
// Eponyme validates and hands you the data. Nothing is stored.
contact: form({
  fields: { /* … */ },
})
```

```ts [managed]
// Eponyme validates, stores the submission, and lists it in the dashboard.
contact: form({
  fields: { /* … */ },
  submission: {
    mode: 'managed',
    maxStored: 10_000,
    retentionDays: 365,
  },
})
```
::

`custom` is the default, so a form never writes to your database unless you ask. In that mode there
is no POST route at all: delivery, storage and side effects are yours.

### Collecting a custom form anyway

`store: true` keeps the dashboard list without giving up the route. Your handler decides what to
accept – a captcha, a signature, a rate limit – then hands the payload over:

```ts [eponyme.config.ts]
contact: form({
  fields: { /* … */ },
  submission: { mode: 'custom', store: true },
})
```

```ts [server/routes/api/contact.post.ts]
const { submission, errors } = await storeEponymeFormSubmission('contact', body)
if (errors) {
  setResponseStatus(event, 422)
  return { errors }
}
```

The helper validates on the way in, so a payload you assembled yourself is held to the same schema.
It throws when the form does not declare `store: true`, rather than dropping the submission
silently. Nothing else changes: there is still no public POST route, and the source of a submission
stays your own handler – a webhook or an import can call it just as well as a form page.

#### Applying the same rate limits

A `custom` route never touches the module's endpoint, so none of the [anti-abuse
protections](#anti-abuse) that endpoint applies are in force – including the rate limits. One line
opts back into them:

```ts [server/routes/api/contact.post.ts]
export default defineEventHandler(async (event) => {
  await assertEponymeFormRateLimit(event, 'contact')

  const body = await readBody(event)
  // …
})
```

It applies the same two windows a `managed` form gets, reads the same `rateLimits.formPerIp` and
`formGlobal` settings, and throws a `429` carrying `Retry-After` – so an unguarded `await` is all
you need.

Call it **before reading the body**: a limit that runs afterwards has already paid for the request
it was meant to refuse. Skip it entirely for a call with no incoming request, such as a webhook
replay or an import.

## Rendering

There is no form component, on purpose: a public page must not inherit the dashboard's theme,
TipTap or reka-ui. `useEponymeForm()` gives you the fields, the values and the errors, and your page
owns every element.

```vue [app/pages/contact.vue]
<script setup lang="ts">
const { fields, errors, honeypot, pending, submitted, submit, reset } = useEponymeForm('contact', {
  async onSubmit(data) {
    // `custom` mode only: data is validated and typed
    await $fetch('/api/contact', { method: 'POST', body: data })
  },
})
</script>

<template>
  <form @submit.prevent="submit()">
    <div v-for="entry in fields" :key="entry.name">
      <label :for="entry.name">{{ entry.label }}</label>
      <input
        :id="entry.name"
        :value="String(entry.value ?? '')"
        :aria-invalid="entry.errors.length ? true : undefined"
        @input="entry.update(($event.target as HTMLInputElement).value)"
      >
      <p v-for="message in entry.errors" :key="message">{{ message }}</p>
    </div>

    <input v-if="honeypot" :name="honeypot" type="text" tabindex="-1" autocomplete="off" hidden>
    <button type="submit">{{ pending ? 'Sending…' : 'Send' }}</button>
  </form>
</template>
```

## Server-side validation

Client-side validation only improves feedback, never the security boundary. In `custom` mode,
validate again in your own route with the auto-imported helper:

```ts [server/routes/api/contact.post.ts]
export default defineEventHandler(async (event) => {
  const body = await readBody(event)
  const result = validateEponymeForm('contact', body)
  if ('errors' in result) {
    setResponseStatus(event, 422)
    return result
  }
  await sendEmail(result.data)
  return { submitted: true }
})
```

## Anti-abuse

Four protections apply to a `managed` form:

- a **honeypot** field, `_eponyme_hp` by default. A filled honeypot gets the normal success
  response and stores nothing, so a bot learns nothing from the answer. `honeypot: false` disables
  it, or pass another name.
- a **body size limit**, 64 KB by default via `maxBodyBytes`. An oversized body is refused with
  `413`, and the request stream is cancelled as soon as it crosses the threshold, including for a
  chunked request without `Content-Length`.
- two **rate limits**, per client/form and global/form. They are shared by every server instance –
  counted in PostgreSQL, or in Redis when [`cacheStorage`](/advanced/caching) points at one – and
  return `429` with `Retry-After`; configure them with `eponyme.rateLimits.formPerIp` and
  `formGlobal`.
- a **stored-row quota and retention window**, configured with `submission.maxStored` (10,000 by
  default) and `submission.retentionDays` (365 by default). Set either to `false` to disable that
  control. Cleanup runs at startup and before every stored submission.

::note
The application limiter is deliberately in addition to an edge/CDN limiter, not a replacement for
one. Captcha remains a host concern: put the widget in your page and verify its token in a `custom`
handler before calling `storeEponymeFormSubmission()`.
::

## Submissions in the dashboard

A form that collects submissions – `managed`, or `custom` with `store: true` – gets a submissions
page with pagination, search and deletion. Rows are selected with the tickbox in their first
column, and the whole page at once from the one in the header; the selection is then deleted in a
single call. It stays on the page it was made on, since the next page is a different set of rows.
Retention and the stored-row quota are configured in `form()`; export is not implemented yet.
