# Content variables

A published value can carry `{{ variables }}`, resolved when the page is served rather than when it was
saved. A footer that reads `© {{ currentYear }}` is written once and never needs touching again.

```ts
copyright: field.string({ defaultValue: '© {{ currentYear }} {{ clubName }}' })
```

## Built in

These are always available, whatever the application configures.

| Variable | Value | Example |
|---|---|---|
| `{{ currentYear }}` | The year at the time the page is served | `2026` |
| `{{ nextYear }}` | The year after, useful for a season spanning two | `2027` |
| `{{ previousYear }}` | The year before | `2025` |
| `{{ currentMonth }}` | Localised month name | `July` |
| `{{ currentDay }}` | Day of the month | `29` |
| `{{ today }}` | Localised date | `29 July 2026` |
| `{{ currentDate }}` | Machine-readable date | `2026-07-29` |

## Your own

Declare them in `eponyme.variables.ts`, at the root of the application. A bare value is enough; the
object form adds a label and a description, which is what the dashboard shows editors when it lists
what they can insert.

```ts [eponyme.variables.ts]
import { defineEponymeVariables } from '@karibsen/eponyme/config'

export default defineEponymeVariables({
  clubName: 'AS Chelles Athlétisme',
  season: {
    label: 'Season',
    description: 'The sporting season, spanning two calendar years.',
    value: () => `${new Date().getFullYear()}-${new Date().getFullYear() + 1}`,
  },
})
```

A function is called on **every read**, so the value stays current without anyone re-saving the
content. That is the whole point: `{{ season }}` rolls over on its own at the turn of the year.

Your variables win over the built-ins, so declaring `today` with your own wording replaces it rather
than colliding with it.

## Where replacement happens

Server-side, in the public read routes: `/api/eponyme/**` and `/api/eponyme-collections/**`. Three
consequences worth knowing:

- **The stored content is never altered.** What is in the database is the source text, `{{ season }}`
  included.
- **The dashboard sees the source.** Reads with `?raw=1` skip replacement, which is what lets an editor
  edit the variable instead of its result.
- **Collections go through the same interpolation**, so a listing shows resolved values like a single
  entry does.

## What a variable is not

```ts
// A name, always. Never an expression.
const VARIABLE_PATTERN = /\{\{\s*([A-Z_]\w*)\s*\}\}/gi
```

::important
`{{ new Date().getFullYear() }}` is **not** evaluated: it is left in the output verbatim. Content is
editable from the dashboard, so evaluating code found in it would hand an editor arbitrary execution on
the server. An unknown name is left verbatim too, rather than silently blanked, so a typo is visible on
the page instead of turning into a hole.
::

A variable whose function throws resolves to an empty string. One broken variable must not take the
whole page down with it.
