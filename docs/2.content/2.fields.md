# Fields

A field is declared with a `field.*` constructor and produces a typed value. The type of your
content follows the declaration, so `data.title` is a `string` and `data.tags` is an array of the
exact tags you allowed.

## Common options

Every constructor accepts these:

| Option | What it does |
|---|---|
| `label` | Shown in the dashboard. Derived from the field name when omitted |
| `description` | Helper text under the control |
| `required` | Enforced when publishing, not while drafting |
| `defaultValue` | Used when the entry is created, and backfilled when the field is added later |
| `visibleWhen` | Shows the field only when another field matches a value |
| `validate` | A synchronous validator returning `true`, or a message |

```ts
field.string({
  validate: (value, data) => value !== data.slug || 'The title must differ from the slug.',
})
```

## Reference

| Constructor | Value | Own options |
|---|---|---|
| `field.string()` | `string` | `minLength`, `maxLength`, `showCounter`, `placeholder`, `trim`, `regex` |
| `field.textarea()` | `string` | same as `string` |
| `field.richText()` | HTML `string` | `minLength`, `maxLength`, `showCounter`, `placeholder` |
| `field.slug()` | `string` | `minLength`, `maxLength`, `showCounter`, `placeholder` |
| `field.email()` | `string` | text options, plus email validation |
| `field.phone()` | E.164 `string` | `countries`, `defaultCountry`, `detectCountry`, `autocomplete`, `placeholder` |
| `field.url()` | `UrlValue` | `protocols`, `placeholder` |
| `field.number()` | `number` | `min`, `max`, `step`, `slider`, `prefix`, `suffix` |
| `field.money()` | `number` | number options, plus `currency`, `symbol`, `position` |
| `field.boolean()` | `boolean` | none |
| `field.file()` | URL `string` | `accept`, `maxSize`, `placeholder` |
| `field.image()` | URL `string` | same as `file`, plus `sources`, with `accept: ['image/*']` and a preview |
| `field.select()` | literal `string` | `options`, `placeholder` |
| `field.radio()` | literal `string` | `options` |
| `field.checkboxGroup()` | literal `string[]` | `options`, `minItems`, `maxItems` |
| `field.tags()` | literal union or `string[]` | `suggestions`, `allowCustom`, `minItems`, `maxItems`, `placeholder` |
| `field.date()` | `YYYY-MM-DD` | `min`, `max`, `defaultValue: today()` |
| `field.datetime()` | UTC ISO `string` | `min`, `max`, `defaultValue` |
| `field.duration()` | milliseconds `number` | `min`, `max`, `defaultValue` (`number` or `h min s ms` string) |
| `field.color()` | hex `string` | `presets`, `allowCustom` |
| `field.relation()` | slug `string` or `string[]` | `to`, `multiple`, `maxItems` |
| `field.array()` | typed array | `of`, `minItems`, `maxItems`, `addLabel`, `itemLabel`, `collapsed`, `showCounter` |
| `field.section()` | typed object | `fields` |
| `field.tab()` | object keyed by tab | `tabs` |

## Custom fields

A project can add its own leaf field by placing one TypeScript definition and one Vue component
with the same lowercase name in `eponyme/fields`. Eponyme discovers the pair at build time; there
is no `nuxt.config.ts` list to maintain.

```ts [eponyme/fields/rating.ts]
import { defineEponymeField } from '@karibsen/eponyme/config'

export interface RatingFieldOptions {
  min?: number
  max?: number
}

export default defineEponymeField<number, RatingFieldOptions>({
  defaultValue: 3,
  normalize: value => typeof value === 'string' ? Number(value) : value,
  validate(value, options) {
    const min = options.min ?? 1
    const max = options.max ?? 5
    return typeof value === 'number' && Number.isInteger(value) && value >= min && value <= max
      ? true
      : `Must be an integer from ${min} to ${max}.`
  },
})
```

The matching component receives `modelValue`, the field `options`, `disabled`, `errors`, `id`,
`label` and `description`, and emits `update:modelValue`:

```vue [eponyme/fields/rating.vue]
<script setup lang="ts">
import type { EponymeCustomFieldComponentProps } from '@karibsen/eponyme'
import type { RatingFieldOptions } from './rating'

const props = defineProps<EponymeCustomFieldComponentProps<number, RatingFieldOptions>>()
const emit = defineEmits<{ 'update:modelValue': [value: number] }>()
</script>

<template>
  <input
    :id="props.id"
    type="number"
    :min="props.options.min"
    :max="props.options.max"
    :value="props.modelValue"
    :disabled="props.disabled"
    @input="emit('update:modelValue', Number(($event.target as HTMLInputElement).value))"
  >
</template>
```

Use the registered name in `eponyme.config.ts`:

```ts
rating: field.custom('rating', {
  label: 'Rating',
  min: 1,
  max: 5,
})
```

The generated registry preserves `rating` as a `number` in content data. Defaults,
normalization, server validation, schema fingerprints, imports, exports and reconciliation follow
the same paths as built-in fields, including inside sections, tabs and arrays. Custom fields are
leaves: `fields`, `tabs` and `of` are reserved for the built-in containers.

## Files and images

`field.file()` stores the URL a file is served from, and `field.image()` is the same field with
images preselected and a picture preview.

```ts
cover: field.image({ label: 'Cover image' }),
brochure: field.file({ label: 'Brochure', accept: ['application/pdf'], maxSize: 5 * 1024 * 1024 }),
```

With [storage configured](/advanced/storage), the field uploads: drop a file on it, pick one from
the media library, replace it, or clear it. `accept` and `maxSize` narrow the module-wide limits
for this field – they cannot widen them.

Without storage, the field is an address typed by hand. That is deliberate: a project that never
configures a bucket still gets a usable field, and an `image` written before storage existed keeps
its value. The stored value is a URL either way, so nothing has to be migrated when a bucket
arrives later.

`field.image()` can also narrow where a picture may come from. `sources` takes `absolute` for an
address on another site, `relative` for a path on this one, and `upload` for a file in the media
library, and defaults to all three:

```ts
// only the media library: no hotlinking to somebody else's server
logo: field.image({ label: 'Logo', sources: ['upload'] }),
```

The editor drops the controls a field cannot use - restricted to `upload`, it offers no address
box - and the API applies the same rule on write, so a value assembled elsewhere is refused too.

## Slugs

`field.slug()` normalises what is typed into lowercase ASCII separated by hyphens. A collection's
slug field is immutable once the entry exists, so a public URL never changes under a visitor.

## Links

`field.url()` stores an object rather than a plain string:

```ts
interface UrlValue {
  href: string
  type: 'internal' | 'external'
  openInNewTab: boolean
  download?: boolean
}
```

An internal link has to start with `/` or `#`. An external one has to use an allowed protocol,
`['http', 'https']` by default:

```ts
website: field.url({ protocols: ['https'] }),
contact: field.url({ protocols: ['mailto', 'tel'] }),
```

The scheme is read up to the colon rather than as a whole prefix, which is what makes `mailto:` and
`tel:` (neither of which has a `//`) declarable at all. Comparison ignores case, `'https://'`
works as well as `'https'`, and the common schemes are autocompleted while any other is accepted.

## Phone numbers

`field.phone()` always stores E.164 (`+33611131143`), whatever format was typed. Normalisation
happens on the server before the write, so the stored format is a guarantee rather than a
convention a client could skip.

```ts
phone: field.phone({
  countries: ['FR', 'BE'],   // ISO 3166-1 alpha-2, autocompleted
  defaultCountry: 'FR',      // assumed when the number has no `+`
  autocomplete: 'tel',
})
```

A number resolving to a country outside `countries` is refused, with an error naming the country it
came from. `detectCountry: false` requires the international `+…` form, so the country is never
guessed.

::note
Validation uses the `min` metadata bundle of `libphonenumber-js`: every country for a fraction of
the size of the full one, at the cost of being slightly permissive: a few numbers that are
impossible for their region still pass.
::

## Numbers

`prefix` and `suffix` name the unit a number is written in. They are shown inside the input, and in
the value readout when `slider` is on:

```ts
price: field.number({ min: 0, prefix: '€', suffix: '/month' }),
```

They are display-only. The stored value is the bare number, and validation never sees them, so
adding or changing a unit never touches saved content.

Declaring `min: 0` also opts the field into the compact numeric keypad on mobile. A field that
accepts a negative keeps the browser's default keyboard instead, because the compact keypad has no
minus key.

## Money

`field.money()` is a `field.number()` that already knows its currency:

```ts
price: field.money({ currency: 'USD', min: 0 }),   // $ before the amount, step 0.01
yen:   field.money({ currency: 'JPY' }),           // ¥ before the amount, step 1
euro:  field.money(),                              // € after the amount, step 0.01
```

The symbol goes where that currency puts it – `$12.00` but `12,00 €` – and the step follows the
currency's minor unit, so yen, won and CFA francs step by 1 rather than offering an amount that
cannot exist. `symbol` and `position` override either choice, for a currency the list does not
carry:

```ts
sats: field.money({ symbol: 'sats', position: 'suffix', step: 1 }),
```

Currencies: `USD`, `EUR`, `GBP`, `JPY`, `CNY`, `KRW`, `INR`, `CHF`, `CAD`, `AUD`, `NZD`, `HKD`,
`SGD`, `SEK`, `NOK`, `DKK`, `PLN`, `CZK`, `BRL`, `MXN`, `ZAR`, `TRY`, `AED`, `MAD`, `XOF`.

The stored value is a plain `number` – the currency lives in the schema, never in the data. That
is also why a field can be switched between `number` and `money` without invalidating an export:
the schema fingerprint an import is checked against sees the same type either way.

::note
`min` is left to you. An amount can be a discount or a balance, so `field.money()` never decides
on its own that a negative value is impossible – and it is `min: 0` that opts a field into the
compact numeric keypad.
::

## Rich text

`field.richText()` stores HTML. Because it is the one field whose value is markup, it is the one
field where a stored value could otherwise become script on a public page – so the server reduces
it, on every write, to the HTML the editor is able to produce:

| | Allowed |
|---|---|
| Tags | `p`, `br`, `h2`, `h3`, `blockquote`, `ul`, `ol`, `li`, `pre`, `hr`, `strong`, `em`, `s`, `u`, `code`, `a`, `img`, `span`, `table`, `colgroup`, `col`, `tbody`, `tr`, `th`, `td` |
| Attributes | `href`, `target`, `rel`, `download` on a link; `src`, `alt`, `title` on an image; `start` on an ordered list; `colspan`, `rowspan`, `colwidth` on a cell; `span` on a column |
| Styles | `text-align: left \| center \| right` on a paragraph, heading or cell; `color` and `background-color`, as a hex or `rgb()` value, on a `span`; `width` and `min-width`, in pixels, on a table or column |
| Protocols | `http`, `https`, `mailto`, `tel`, plus `/path` and `#anchor` internal links |

Everything else goes: `script`, `iframe`, `object`, `embed`, active SVG, `on*` handlers, any other
`style` declaration, and `javascript:`, `data:` or `//host` URLs. A link opening a new tab is given
`rel="noopener noreferrer"` whether or not it arrived with one.

This runs before the write, so it covers saving, publishing, restoring a version and importing a
file alike – a portable export is only as trustworthy as wherever it has been.

::note
A save whose HTML loses something to this policy is refused with a `422` naming the field, rather
than quietly cleaned. The editor cannot produce that markup, so either the payload was rewritten on
its way in, or an editor is about to lose formatting still visible on their screen. Reformatting
alone – `<br>` stored as `<br />` – is not a refusal.
::


### Tables

The toolbar's table menu inserts a three-by-three grid with a header row, then adds and removes rows
and columns, merges and splits cells, and deletes the table. What the menu offers is what the
selection allows, so nothing outside a table is ever proposed.

Columns are deliberately not resizable. A width dragged on one screen is a width stored for every
reader, and the widths the extension computes on its own are the only ones the sanitiser accepts.

A `{{ variable }}` resolved inside rich text is HTML-escaped, so a value the host computes from
data it does not control cannot reintroduce markup after the fact. In every other field type a
variable stays plain text, ampersand included.

To render it, use the component rather than `v-html`:

```vue
<EponymeRichText :html="article.body" as="article" />
```

## Tags

`field.tags()` holds a short list of values, with suggestions and optional free entry.

```ts
tags: field.tags({
  suggestions: ['Nuxt', 'Vue', 'TypeScript'],
  allowCustom: true,
  maxItems: 5,
})
```

The value type follows the options: closed, it is `('Nuxt' | 'Vue' | 'TypeScript')[]`; with
`allowCustom`, `string[]`. One array never mixes two types.

The list is normalized on the server: trimmed, blanks dropped, duplicates folded case-insensitively.
A suggestion imposes its spelling, so typing `nuxt` beside a declared `Nuxt` yields `Nuxt` and a
listing never splits in two. `minItems` and `maxItems` count what is left after that folding.

## Colors

`field.color()` holds a hex string, picked from a palette or from the browser's own picker.

```ts
accent: field.color({
  presets: ['#111827', '#2563eb', '#f97316'],
  allowCustom: false,
})
```

`presets` overrides the module-wide `colorPresets` for this field. `allowCustom: false` drops the
native picker, so a brand palette stays the only thing an editor can choose from.

## Dates

```ts
publishedOn: field.date({ defaultValue: today() })
```

`today()` returns a marker rather than a date. The local day is resolved when the default values are
created, not when the module was built.

`field.datetime()` adds a local date-and-time input with minute precision. Editors work in their
browser's time zone, while Eponyme stores one canonical UTC instant:

```ts
publishedAt: field.datetime({
  min: '2026-01-01T00:00:00.000Z',
})
// Stored value: 2026-08-08T12:30:00.000Z
```

## Durations

`field.duration()` displays separate hour, minute, second and millisecond controls. Hours are not
capped; minutes and seconds range from 0 to 59, and milliseconds from 0 to 999. The database value
is always one non-negative integer of milliseconds.

Readable strings make field configuration easier and are converted immediately with `toMs`:

```ts
import { field, toMs } from '@karibsen/eponyme/config'

readingTime: field.duration({
  defaultValue: '1h 10min',
  min: '30s',
  max: toMs('12h'),
})

toMs('1h 2min 3s 4ms') // 3_723_004
```

Both `datetime` and `duration` are dashboard authoring fields and cannot be used in a public
`form({ fields })`.

## Groups

`field.section()` groups fields into one object, `field.tab()` into one object per tab, and
`field.array()` repeats either a single field or a whole schema. A section may hold another
section; an array item stays a plain field.

```ts
hero: field.section({
  label: 'Hero',
  fields: {
    title: field.string({ required: true }),
    introduction: field.textarea(),
  },
}),
people: field.array({
  label: 'Team',
  of: {
    name: field.string({ required: true }),
    role: field.string(),
  },
  minItems: 1,
  itemLabel: '$name — $role',
}),
```

`itemLabel` is the heading of each item. `$i` is its position and `$<field>` the value that field
holds in that item, so the heading follows what is being written – `Member $i` still works, and an
item whose interpolation is still empty falls back to `Item $i`. An array of plain values reads
`$value`.

Every item folds shut from its heading, and `collapsed: true` starts them all folded. Past eight
items a search box filters the list – dragging is suspended while a query hides anything, since a
filtered list is not the order the value is stored in.

A field added inside a section, a tab or an array item gets its `defaultValue` backfilled on the
next read, exactly like a field added at the root.

## Relations

`field.relation()` points at an entry of a collection, by slug.

```ts
featured: field.relation({ to: 'articles' }),
related: field.relation({ to: 'articles', multiple: true, maxItems: 3 }),
```

The stored value is the slug, or a list of them – a slug is fixed at creation, so a reference
stays valid for the life of the entry and stays readable in an export. The dashboard renders a
picker with a search box and a pager, and a relation goes wherever a plain field goes, including
inside a section, a tab or an array item.

Reading a relation gives the reference, not the target: the page decides whether it needs the
content behind it.

```ts
const { data } = await useEponyme('pages/home')
const { data: article } = await useEponymeCollectionEntry('articles', data.value.featured)
```

A relation declared at the root of a collection is filterable like a `select()`, so
`where: { featured: 'my-article' }` works on a listing.

::note
A reference may point at an entry that is still a draft. Nothing special happens: reading that
entry publicly returns nothing until it is published, exactly as it would anywhere else.
::

::warning
An entry another one still points at cannot be moved to the trash. The refusal is a `409` naming
the entries that hold the reference, so an editor knows what to detach first – a draft holding
one counts, since it would break just the same. Writing a reference to an entry that does not
exist is refused with a `422` on the field.
::

## Blocks

A group of fields written once and placed in several schemas. `defineBlock()` is auto-imported;
the block itself is imported where it is used.

```ts
// eponyme/blocks/call-to-action.ts
export const callToActionBlock = defineBlock({
  name: 'callToAction',
  label: 'Call to action',
  description: 'Heading and button shown at the end of the page.',
  fields: {
    heading: field.string({ required: true, maxLength: 80 }),
    href: field.url({ label: 'Button link' }),
  },
})
```

```ts
// eponyme.config.ts
import { callToActionBlock } from './eponyme/blocks/call-to-action'

contact: {
  title: field.string(),
  callToAction: callToActionBlock(),
},
articles: collection({
  fields: {
    title: field.string({ required: true }),
    callToAction: callToActionBlock({ label: 'Article call to action' }),
  },
}),
```

A call site may pass `label`, `description` and `visibleWhen`. It cannot change what the block
holds: a block owns its fields, a page owns how it is introduced and when it is shown.

What a block produces is a plain `field.section()`, the way `field.seo()` does – so it goes wherever
a section goes: at the root of a schema, inside a tab, or inside another section. Validation,
storage, the index and the schema fingerprint all see a section, and nothing needs to know a block
was involved.

A section nested in another section – which is what a block inside a tab is, since a tab is a
section – is drawn as a card that folds shut, rather than as a chapter of the page.

::note
`name` is the block's identity, not part of its data: it is stored nowhere and read by no
fingerprint. Renaming a block, or relabelling it at one call site, cannot invalidate an export
made before. It exists so a later migration can name the block it is migrating.
::

::warning
Each call site keeps its own copy of the values. Two pages using the same block share its shape,
never its content – editing one leaves the other untouched.
::

## Conditional fields

```ts
subtitle: field.textarea({
  visibleWhen: { field: 'published', equals: true },
})
```

A hidden field is not validated, so a `required` field the author cannot see never blocks a
publication.
